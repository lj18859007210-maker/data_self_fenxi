# 数据自分析大屏 — 设计文档

## 1. 概述

构建一个通用数据自分析平台，用户上传任意结构化数据（CSV/Excel），系统自动对所有字段进行全面分析，含单字段分析和跨字段关联分析，并以交互式仪表盘呈现结果。分析能力对标 Tableau / Power BI / 网易有数等一线 BI 工具。

### 核心原则

- **零配置分析**：上传即分析，无需用户指定维度/度量
- **全自动洞察**：AI 引擎自动发现数据中的模式、异常和关联
- **兼顾深浅**：技术用户可深入探索，业务用户能快速理解
- **百万行级**：后端分析引擎支撑百万行数据秒级响应

## 4. 功能模块

### 4.1 数据接入模块

- **文件上传**：支持 CSV（含编码自动检测）、Excel（.xlsx/.xls），最大 500MB
- **拖拽上传**：支持点击选择和拖拽两种方式
- **示例数据**：内置 2-3 个示例数据集，让用户立即体验
- **自动类型推断**：上传后自动识别每列数据类型（数值/文本/日期/布尔/分类）
- **数据预览**：显示前 100 行数据表格，标注推断类型
- **类型修正**：用户可手动修正字段类型，纠正自动推断错误
- **文件信息**：显示行数、列数、文件大小、缺失值概览

### 4.2 单字段分析

对每个字段自动生成分析卡片，包含：

| 分析项 | 数值字段 | 类别字段 | 时间字段 |
|--------|---------|---------|---------|
| 描述性统计 | 均值、中位数、标准差、偏度、峰度、极值、四分位数 | 频次、占比、唯一值数 | 时间范围、频率 |
| 分布可视化 | 直方图 + KDE 曲线 | 柱状图/饼图 | 时间序列折线图 |
| 异常检测 | IQR 箱线图、Z-Score 离群标记 | 长尾分布检测 | 趋势断点检测 |
| 质量报告 | 缺失率、无效值、重复值 | 类别平衡性 | 时间间隔一致性 |

### 4.3 跨字段关联分析

| 分析类型 | 技术实现 | 适用场景 |
|---------|---------|---------|
| 相关性矩阵 | Pearson / Spearman 相关系数 | 数值-数值字段 |
| 交叉统计表 | 列联表 + Cramér's V | 类别-类别字段 |
| ANOVA / Eta 系数 | 方差分析 | 类别-数值字段 |
| 散点图矩阵 | 多字段两两散点图 | 多数值字段探索 |
| 分组对比图 | 分组箱线图/柱状图 | 对比不同类别下的数值分布 |
| 时间趋势分解 | 趋势 + 季节 + 残差 | 时间序列字段 |

### 4.4 AI 增强分析

自动洞察引擎，无需用户手动探索即可发现数据价值：

- **自动洞察发现**：扫描所有字段组合，自动发现显著模式
  - 「A 类别下的 B 指标显著高于/低于整体均值」
  - 「X 与 Y 存在强相关性（r=0.87）」
  - 「Z 字段存在 5 个异常值点」
  - 「某维度的分组差异显著（p<0.01）」
- **关键驱动因素分析**：自动识别哪个字段对目标字段影响最大
- **智能图表推荐**：根据字段类型和数据结构，自动推荐最合适的可视化方式
- **异常模式标记**：自动标记数据中的异常模式并解释原因
- **自然语言查询**（NL2SQL，二期）：用户用中文提问，系统转成 SQL 查询

### 4.5 交互式仪表盘

- **全局概览**：顶部展示关键 KPI 卡片（总行数、字段数、缺失率、异常数）
- **AI 洞察栏**：置顶显示自动发现的关键洞察，按重要性排序
- **图表网格**：自动生成的图表网格，用户可拖拽调整布局
- **字段筛选联动**：点击图表元素可联动筛选其他图表
- **图表交互**：悬浮显示详情、缩放、数据导出
- **布局持久化**：保存用户对仪表盘的布局调整

## 5. 数据流

```
用户上传文件
    │
    ▼
[前端] 接收文件，显示上传进度
    │ POST /api/upload
    ▼
[后端] 接收并存储文件到暂存目录
    │
    ▼
[后端] 自动分析阶段（全异步）：
    │
    ├── 1. Polars 读取文件，自动推断类型
    ├── 2. DuckDB 导入数据（直接基于文件查询，无需 ETL）
    ├── 3. 计算单字段统计量（分布、异常、质量）
    ├── 4. 计算关联分析（相关性矩阵、交叉表）
    ├── 5. AI 洞察引擎（异常检测、关键驱动）
    └── 6. 汇总结果，生成分析报告 JSON
    │
    ▼
[前端] 轮询/WebSocket 获取分析进度
    │ 进度更新 → 逐步渲染图表
    ▼
[前端] 分析完成 → 展示完整仪表盘
```

### 关键数据约束

- **分析触发**：用户点击「开始分析」后才触发后端计算，非上传即触发
- **分批渲染**：前端轮询进度，单字段分析完成即可逐步展示，无需等全部完成
- **缓存策略**：分析结果缓存到 DuckDB 的临时表，同一文件重复查看无需重新计算
- **前端渲染**：ECharts 负责百万级数据点的高性能渲染，后端只返回聚合后的图表数据

## 6. API 设计

### RESTful 端点

| 方法 | 路径 | 功能 |
|------|------|------|
| POST | `/api/upload` | 上传文件，返回 `session_id` 和字段信息 |
| GET | `/api/sessions/{id}/preview` | 获取数据预览（前 100 行 + 字段信息） |
| PUT | `/api/sessions/{id}/fields` | 修正字段类型配置 |
| POST | `/api/sessions/{id}/analyze` | 触发全量分析（异步） |
| GET | `/api/sessions/{id}/progress` | 轮询分析进度 |
| GET | `/api/sessions/{id}/overview` | 获取仪表盘概览 KPI |
| GET | `/api/sessions/{id}/fields/{field}` | 获取单字段分析结果 |
| GET | `/api/sessions/{id}/correlation` | 获取相关性矩阵 |
| GET | `/api/sessions/{id}/insights` | 获取 AI 洞察列表 |
| GET | `/api/sessions/{id}/charts` | 获取所有自动生成的图表配置 |

### 响应格式（统一）

```json
{
  "success": true,
  "data": { ... },
  "error": null,
  "meta": {
    "elapsed_ms": 1234,
    "rows": 1000000,
    "columns": 12
  }
}
```

## 10. 扩展性设计

- **分析引擎插件化**：每个分析项（统计量/相关性/异常检测等）实现为独立插件，可单独启用/禁用
- **ECharts 按需加载**：只加载用到的图表类型，减小前端包体积
- **查询缓存**：相同分析请求直接返回缓存结果
- **DuckDB 的分区能力**：当单文件超过千万行时，自动启用分区查询
- **前端代码分割**：按路由懒加载，仪表盘页面才加载 ECharts
